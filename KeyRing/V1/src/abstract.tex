\begin{abstract}
% 1. State the problem
Enterprise analytics, BI tools, and LLM agents rely on a join graph that identifies joinable tables, key columns, and reference directions. Discovering this graph is difficult: enterprise databases contain thousands of tables, rarely declare foreign keys, and continually ingest new tables. 
% 2. Say why it's an interesting problem
Statistical methods frequently mistake accidental value overlap for true joins or miss keys that differ in name and format. LLM-based pairwise verification can resolve these ambiguities but is prohibitively expensive, produces inconsistent and redundant edges, and must be repeated for every arriving table; the resulting dense graphs further expose downstream queries to unnecessary join paths and intermediate results.
% 3. Say what your solution achieves
We present \ourmethod, a hybrid system that discovers joins by identifying candidate \emph{key domains} rather than table pairs. Each domain consists of a unique owner column and the columns that reference it. \ourmethod profiles columns once, then uses value containment, semantic embeddings, and format normalization to generate high-recall candidate domains, elect owners, group references, and prune generic columns that would otherwise match unrelated keys. An LLM verifies each candidate domain in a single batched prompt instead of verifying every constituent pair. Confirmed domains yield a compact, owner-centered (star-shaped) join graph that retains verified joins without redundant edges and supplies explicit key directions to downstream processors.
% 4. Say what follows from your solution
Under the assumption of $\todo{N}\times$ higher efficiency and accuracy relative to state-of-the-art systems, \ourmethod reduces LLM calls and tokens by the same factor range versus blocked pairwise verification while retaining the large majority of true joins, improves F1 over the strongest non-LLM baseline, and achieves high precision on human-labeled joins. In the online setting it links arriving tables with substantially fewer LLM calls than pairwise methods. Downstream systems that consume the resulting graph exhibit improved query performance through fewer alternative join paths and reduced intermediate results, without altering query answers.
\end{abstract}
